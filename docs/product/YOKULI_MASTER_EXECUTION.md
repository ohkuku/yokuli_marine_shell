# Yokuli OS · 自查、系统接入与通知实施主规则

本文件合并用户于 2026-09-25 提供的实施要求，作为继续同项工作的入口；它是要求，不是完成声明。通知专项的具体生产决策集中在 [通知中心契约](NOTIFICATION_CENTER_CONTRACT.md)，系统现状集中在 [运行时边界](../os/10-INPROCESS-SYSTEM-BOUNDARIES.md)。不维护另一份相互竞争的“最新方案”。

后续明确指示将生产视觉基线从 WP8 升级到 **Windows 10 Mobile / MDL2**；研究来源、适配取舍和共享组件入口集中在 [W10M 设计基线](WINDOWS_10_MOBILE_DESIGN.md)。历史 WP8 资料保留，但不能覆盖当前指示；视觉迁移不重写业务所有者、请求回执、来源或返回关系。后续用户明确保留经典应用开合/Home 翻转，当前实现将它与 W10M 控件和透明开始屏幕组合，不恢复旧式超大标题。

## 每轮实际工作

同时推进两条线：沿用户任务直接修复源码确认的问题；沿现有唯一运行时完成一个真实客户端已接入的系统能力闭环。当前通知中心专项包括消息/任务/警报分离、跟手关闭、四个快捷入口、独立任务卡、结构化消息、可清除与可见已读、通知返回链、持久化故障恢复。

执行顺序为：核对当前 HEAD 和生产入口 → 定位所有者及真实问题 → 修改业务和 UI → 替换实际调用方 → 同步权威指导文档。不要复读完整仓库后才开始修改，不在旧页、Preview、假数据或未调用接口中交付。现有正常能力与用户资料必须保留。

自查沿海图与对象详情互跳、导航与独立记录、守锚开始与恢复、来源丢失与修复、消息查看/清除/处理、AIS 跨视图对象、持久化失败与重新进入进行。优先解决数据错误、虚假成功、警报语义、资源重复和资料丢失，再处理任务走不通、导航混乱、通知交互及接入障碍。没有源码或运行证据时不宣称已复现，也不以大范围重写掩盖不确定性。

## 轻量功能与对象操作（experience.19）

- 地点先在海图同一场景中预览，普通单点前往直接展示几何路径，多点才需要起点选择。摘要、完整详情与跨应用调用保留对象 ID 和来路；修复来源后返回原预览。
- `TripRuntime.captureMoment` 在点击入口捕获所属航程、时刻和规范数据快照，先提交捕获日志及原事件表，再允许补名称、类型、文字。原数据和来源证据不可因编辑而重采；失败保留同 ID 重试。缺少合格位置为 null，暂停状态补记不等于继续采集。
- 来源替换由现有运行时准备候选、检查资格再采用，等待期间保留原来源。守锚运行时明确拒绝换源，不能把自动暂停当成便利步骤。固定手机以确认姿态为零点，旧版本校准不可假装已迁移。
- 新功能先利用现有对象摘要、来源修复、通知任务与分享入口，避免再造总控首页。一次只有一个对象展开完整详情，地图、三维相机及业务任务的所有者保持稳定。
- 本批实现附加文档的 A–D，并将航程分享收敛为三个用途。路线资料准备、最近时刻搜索与视图预设尚未作为新增能力交付；天气/潮汐需要真实提供方、许可与缓存链路，不创建空壳入口。

## 后续使用反馈（experience.20）

背景和透明磁贴应在设置及磁贴编辑中有明确入口，未选照片也可发现相关选项；预览与桌面共享实际绘制。全尺度单位、比例尺和尺寸的语义见 [总拓扑](OS_INTERFACE_TOPOLOGY.md#全尺度单位与系统偏好)。雷达场景不叠放系统边缘弧光或无必要的圆形信息按钮。姿态平滑只属于显示层，不能改变采集、来源与保护规则。详细动作及生命周期参数继续维护于现有 W10M 设计文档。

## 全局动画与可信历史（experience.21）

Shell 开合、通知、磁贴、任务卡和实时仪表采用系统帧时钟及绘制层状态，保留原访问栈与 Home 翻转；刷新率请求不等于达到某一设备帧率的证据。历史数据必须保留真实时间、数值和来源连续段，禁止用心跳重记旧值或覆盖已经显示的采样点。回看轴固定并明确标出截止时刻，新增数据由显式更新进入当前视图；各类图形的选择与交互统一维护于 [仪表契约](INSTRUMENT_TILE_CONTRACT.md)，持久气压及来源语义见 [数据中心契约](DATA_CENTER_CONTRACT.md)。

### 航线预览入口与磁贴悬浮补齐（2026-09-26）

`RouteScreen` 中整条航线预览和航点定位共用一个 `preview(focus)` 回调，实际调用 `WpShellRuntime.showChartRoutePreview`。在打开地图前结束当前及保留返回快照中的编辑展示，保留草稿与导航会话。查看航点是只读定位，不重新打开编辑准星；显式返回当前导航也先清理预览和编辑展示。关闭地图上的预览继续使用已存在的 X 和 `hideChartRoutePreview`，不创建第二套隐藏名单或路线状态。

`WpSpatialStartLayout` 承接选中与拖动的悬浮层级、抬升、阴影和轻微倾斜；原 `WpTile` 的选中缩放保留，只在拖动时额外放大。连续数值仅在 placement / graphicsLayer 读取，不播放循环摇摆，也不改壁纸、透明度、主题或磁贴色板。松手和取消从最后实际绘制位置收敛到 packer 的格位，末帧显式归整；落下途中再次抓取从当前画面位置接续，不先跳回格位。参数是本产品的动效适配，不是微软原机实测值；沿用 Compose 帧时钟和宿主动画时长缩放。

以上是生产接线说明，不代替 Android 编译或真机结果。整行收拢、拖动边界、原持久化提交与撤销规则继续由既有实现承担；本次不修改测试或 CI，也不从局部源码生成全量 API 索引。

## 常驻、航行组合磁贴与空间视图（experience.26）

视觉基线仍是扁平、文字主导与黑白内容层级；共用帆船字标几何，业务警报和海图语义色独立保留。用户可在“外观与显示”选择 Windows Phone 风格的预设磁贴/强调色，默认黑白不再意味着删除个性化入口；预设只改变显示层，不重置磁贴内容、布局、背景照片或透明度。磁贴推荐内容按航行、风况、环境、水深余量和船姿组合，单一读数仍可显式选择，透明预览与真实桌面只绘制一块磁贴。图形和来源状态沿用同一可信读投影。

`MarineSystem.residency` 已接入原协调器，持有系统采集需求而不复制传感器或网络源；Settings 与退出磁贴经同一确认入口，先持久停止闩锁，再以有界等待暂停原领域任务、停止采集连接共享，Core 确认停止后立即退出任务；短历史与退出通知只作有界收尾，不能把已停止的系统卡在退出页。无有效船位只阻止依赖实时位置的动作，仍可浏览海图和资料；持续问题进入同一持久通知，带恢复入口和冷却提醒，应用与 Android 镜像共享消息事实及系统声音设置。后台资源、权限和历史范围见生命周期文档。

海图发起的路线/对象查看完成后，通过原访问交付预览结果并返回海图，不能再压入海图访问。AIS 三维使用透视海面与船体；立体方向读取已校准的固定安装姿态，手持平放和横屏保留明确方向表达。显示缓动不改变业务观测或来源时间。

## 必须保持的系统方向

磁贴工坊重构已接入生产，用户故事和实现位置见 [磁贴工坊实施文档](../phases/tile-workshop/IMPLEMENTATION.md)。内容绑定、访问栈、来源与 W10M 既有契约继续承接长期规则。

当前增量包括 ENC 航海表现与实际 Core/Shell 分进程恢复；显示边界和恢复语义分别以海图契约、生命周期与系统边界文档为准，不宣称完整 S-52 Presentation Library 或设备连续运行保证。

文件夹图册与离线航线规划：海图和数据分别管理，一个文件夹代表一种资料集合，一次单选一个，无须创建图层；矢量呈现设置归“数据”而不是背景图层。数据文件夹及单文件可在同一海图预览真实覆盖：GEBCO 低缩放看覆盖、放大后看有界高程分级，矢量对象按现有呈现规则显示；预览不改变当前规划选择。LINZ 与 GEBCO 接入同一资料版本、查询和规划链并保持参考来源限制。自动建议以人工核对为目标：GEBCO 等参考高程可直接作为粗略水陆地形证据，不再要求海图基准“可信深度面”；未设置吃水/UKC 时只做水陆绕行并强制 REVIEW，设置后才检查参考浅水。没有转弯半径也可生成粗略 A* 避让折线，有转弯半径才做圆弧校验；候选立即与原线同图比较，但不会自动采用或开始导航。真实数据格式、文件夹内优先级、原源重扫、当前选择绑定、分析边界和后续环境能力见 [海图契约](CHART_INTERACTION_CONTRACT.md#数据图册与自动规划2026-09-25)。本轮不做潮汐/天气情景，不增加测试或 CI 工作。

```text
Shell / 内置应用 / 获授权客户端
  → 窄领域客户端与能力描述
  → 进程内或 Binder 传输适配
  → 唯一领域运行时
  → 存储、GNSS、传感器、网络、文件、权限与通知适配
  → Android / AOSP
```

- Shell 拥有应用身份、访问栈、系统面板、输入、焦点与动画；UI 拥有相机、筛选、滚动和草稿；领域持有状态机、命令、持久化和恢复。平台与传输不能另造业务规则。
- 规范值与显示单位、UTC 与单调时间、来源身份与连接名称分别建模；不把缺测变成零、不因新字段或页面打开续期旧数据、不偷偷切换固定来源。Heading 不是 COG。
- 导航、记录、守锚和 AIS 分别具有独立生命周期。离开页面、Home、关闭通知和清除历史不改变运行任务；恢复页面不能重放 Start、Resume、Arm、Connect 或 Publish。
- 新功能需要实际读模型、类型化命令及对象 ID、结构化结果、稳定事件、能力、入口、返回关系、持久化与资源释放。纯契约不暴露 Context、Compose、OsStore、Room entity/DAO、控制器或 Job；当前本地兼容签名不等于新公共协议许可。
- 同一领域只能有一个活动写入者。IPC 需要真实客户端、服务、序列化、版本、调用者校验、初始快照、重连与死亡清理；枚举、空 AIDL、常量健康页不构成迁移。传输中断结果未知时查询原 requestId，不换 ID 自动重发副作用。
- 普通 APK 不抢 Android 顶边手势，不读其他应用通知，不以 AccessibilityService、全局 exported 或关闭 SELinux 模拟系统接管。

## 场景磁贴与像素品牌（experience.29）

重要航行场景支持真实 4×4；工坊的复合磁贴可选 2–4 个真实内容、配置顺序与内部打开目标。4／6 列沿原桌面文档保存并重排，预览与实际布局一致。业务运行、来源与历史仍由唯一 Core 持有。字段与接入规则集中在 [仪表磁贴契约](INSTRUMENT_TILE_CONTRACT.md)。

旧大写帆船 O 品牌被本轮用户明确替换。新基线为原创小写字标与十六格像素帆船、扁平黑白；每个新建 Launcher/HOME 任务先绘制一次轻量短帧时钟动画，完整 Shell/Core 接线在完成或略过后启动，不让底层初始化抢占首帧；通知、配置恢复和热返回不重复遮挡。具体生产资产、动画及官方参考见 [设计基线](WINDOWS_10_MOBILE_DESIGN.md#yokuli-品牌标记与字标2026-09-25)。

## 应用中心与 SDK 1（experience.30）

- 应用中心提供离线目录、从文件检查并安装、查看授权、更新和卸载；内置应用始终保留。扩展进入现有应用列表、任务栈、搜索、开始磁贴；扩展只读系统数据，不新增采集来源。
- 两个可安装应用为出航清单和航行看板。清单持久化由用户确认的项目；看板读取实际规范观测，保持来源、时效和全局单位，不代替航行/守锚控制。
- SDK JS UI 库与 Kotlin/JS 模板共享包格式和能力协议。开发者站点与 APK 离线指南由同一打包脚本生成；原生 APK 安装、远程发行者签名商店、后台扩展、第三方 NMEA 写入尚不支持。
- 本轮针对明确指出的回归任务，修复加载时覆盖桌面、撤销额外重排与同尺寸保存副作用，并最小更新已过时的现有回归断言；未停用工作流或忽略失败。其他新功能仍按代码实现范围推进。


## .ykl 内部应用与 SDK 2（experience.31）

- 正式安装格式为 `.ykl`，JS 与 Kotlin/JS 使用同一运行时；保留内置应用及旧安装兼容，不支持 Android APK 插件。应用中心、模板、离线指南和打包输出同步使用新扩展名。
- SDK 2 接入真实设备目录、数据来源选择、已配置 NMEA 连接启停、本机分享启停和共享航行记录命令；新的船上控制台为可安装消费者。控制授权与读取分别管理，记录使用完整持久回执。
- 内置数据中心也使用新的设备目录；不新建传感器和网络数据所有者。experience.31 当时仅交付设备目录；后续虚拟设备、时间与演练接线见下方当前规则，不把旧目录状态继续当成现状。


## 虚拟环境与统一应用包（2026-09-27）

- 演练室通过 `MarineSystem.hardware` 控制真实接入的 GNSS/IMU/气压/NMEA 可替换后端、统一虚拟时间、原始系统记录/回放及场景故障。上层应用仍消费同一解析、来源、导航、守锚和历史链，不新增演示读数。暂停/倍速影响业务时间，宿主 IO、动画和恢复控制继续可用。
- 模拟/回放运行在独立 world 数据与通知空间，模式切换拒绝打断现有守锚、航程及导航；保存选择后重启 Core 存储所有者，Shell 保留任务栈并重连。恢复一律暂停；来源与历史带后端和时间纪元。录制的命令仅作审计，回放不擅自启动保护或外部输出。
- 内置应用清单和用户 `.ykl` 共用目录与任务分派；可信 `host-kotlin` 组件必须编译进签名 APK，外部安装仍只接受 JS/Kotlin/JS web 包。不能将这一组织方式声称为支持任意原生 APK。
- 新功能沿 [领域接入](../os/02-DOMAIN-AND-CONTRACTS.md#虚拟设备时间与持久化接入)使用总线、统一时间、world 路径和授权端口。当前存储故障覆盖 Room、七个 PreferencesDataStore 生产委托与已登记核心文件操作，仍非任意文件系统/SAF 拦截；电源状态不等于控制 Android PM。真实边界、拓扑与缺口集中维护于 [系统边界](../os/10-INPROCESS-SYSTEM-BOUNDARIES.md#虚拟海事运行环境2026-09-27)。
