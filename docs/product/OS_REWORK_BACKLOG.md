## 2. 0.3 代码审计快照

以下保留整改前 0.3 代码的审计事实，解释模型与整改顺序的由来，不代表 0.4 当前实现状态。0.4 的代码接通和验收状态见上表；不能以“模型已写明”或“调用已接通”冒充运行验收通过。路径相对仓库根目录。

### 2.1 全局导航被多个页面解释

- `legacy-marine/.../MainViewModel.kt` 的 `navigationRequests` 广播 Int，额外读取可变 `dataSection` 猜子页。
- `app-shell/src/rebuild/.../WpShellExperience.kt`、`ui/NmeaFlowScreen.kt` 和 `legacy-marine/.../ui/navigation/LegacyMarineScreen.kt` 同时消费。
- 同一个 `1` 被 Shell 解释成仪表，被旧宿主解释成 trip。旧宿主还有全局回放/锚地覆盖状态。
- `TripWatchPage` 是旧 Sail 工作区，不是纯仪表。NMEA 新页又嵌入旧完整连接/输出工作区。
- 旧 `AnchorApp` 四栏根导航当时没有启动调用，不能把未使用的根页面误当现行故障来源。共享语言/告警仍可能与其同文件，不能整文件粗删。

替换为 Shell 唯一跨 App 路由、类型化目的地/结果，各 App 的内部页面局部管理。

### 2.2 航程、来源与后台资源存在冲突

- `legacy-marine/.../data/vessel/VesselDataHub.kt` 使用 `tripPositionPreference ?: shellPositionSource`，活动航程可覆盖用户全局选择。
- `runtime/trip/TripRuntime.kt` 对 NMEA 航程仍申请 `needsSystemLocation=true`。
- 手机位置订阅同时受 app/preview/background 三种开关影响；关闭表面 Data 开关不一定停止后台定位。
- `YokuliRuntimeCoordinator` 启动和恢复流程把 Trip 与 Anchor 互斥，恢复时也可能强制暂停 Trip。
- Trip 暂停/结束及旧对话框关闭有全局安装状态副作用。

必须一起改来源权威、会话共存和资源申请。不能仅删一个禁用条件，或把两个开关合并后留下隐藏来源覆盖。

### 2.3 当时共享地图只共享瓦片

- `Model.kt` 的共享瓦片订阅不包含完整地图来源选择。
- `ChartLibrary.selectedLayers` 可同时启用多文件夹，与单一当前图层冲突。
- `ChartScreen` 的三类模式选择及附加开关不能表达当前哪个命名图层。
- Anchor、选点、历史回放、锚地详情等存在多处旧 GoogleMap，各持本地地图类型/手势/相机逻辑。
- 新 `ChartSurface` 直接读整个 OsStore，需把 scene、局部视野和事件边界抽出来，保留已改善的手势。

### 2.4 多连接不是配置 List 就完成

- `NavigationRepository` 当时只有一个 manager、activeProfile、generation 与合成 fix；换代可清空全部 NMEA。
- `VesselSourceRegistry` / `NmeaCandidateMapper` 已有 profile/generation/句型候选，可复用。
- UDP 当时丢失远端身份；连接内多个发件人必须可区分。
- 输出设置虽有 destinations 列表，实际 publisher/writer/status 仍单例，双向输出必须绑定明确 ConnectionId。
- Anchor、水深采样、模拟输出等仍读取单一合成 fix，不能只给新 NMEA UI 加列表而留下底层混源。
- 本机 TCP 服务已有每客户端队列和多订阅者基础，但当时只写不读、主要发布 Phone 数据；准确限定原有能力。

### 2.5 设置和用户资料的迁移风险

- 原 `LauncherPersistedState` 已存单位、motion 和应用偏好，新 experience JSON 只迁了部分外观配置。
- 原 `AppPreferenceContribution` 和 `MarineDisplayUnits` 可以直接复用；不需重新发明磁贴设置协议。
- 旧锚地 Room 已有 Place / Spot / Visit，Migration19To20 已保留 ID 和关系；不能压扁为新简单 JSON Place，丢掉资料。
- 不同包名的旧 App 私有数据需通过其导出获得；引入源码 library 不等于自动迁入旧安装数据库。

## 3. 按依赖推进的整改顺序

先确定契约，再让一条完整用户故事贯穿底层与界面；不只提交一套没人实际使用的新接口。

### 第一段：数据与控制权

1. 确定唯一来源策略，拆掉 Trip 覆盖来源与强制手机定位；资源获取由系统策略控制。
2. 统一记录命令/状态；允许航程记录与锚警共存，包括恢复、暂停/结束和安装状态的副作用清理。拆开共享命令 actor 中的长定位等待/磁盘工作，不能让锚警确认或暂停被阻塞。
3. 用明确目的地替换全局整数导航；共享选点/来源等返回结果能力与跨 App 跳转分开。
4. Shell 设置恢复单位、原磁贴参数和 Start；船舶资料确定单一权威存储。

完成证据：手机/NMEA 都关闭后无后台偷开；同一记录从海图与日志看到一致状态；离开页面不改变业务；子页返回恢复正确 App。

### 第二段：共享地图与我的航行

1. 当前来源改为 Online/Satellite/CustomLayer，所有入口使用同一选择；保持地图视口和相机。
2. 从新 ChartSurface 提取 scene/viewstate/events，Chart 先接回同一实现。
3. 建立 MySailingRepository 薄适配，统一当前 JSON 和既有 Room 资料的查询/命令，保留 ID 命名空间和来源信息；后续迁库独立处理。
4. 用同一地图先完成坐标预览/选点，再完成锚警业务界面，最后用于日志回放。对应完成后撤下旧地图入口。

完成证据：同一命名图层在海图、锚警和回放中一致；准星出现相机不动；收藏锚地在我的航行只出现一份；修改收藏不移动活动锚警中心。

### 第三段：多 NMEA 与本机角色

1. Transport/session 按 ConnectionId 分区；独立 generation、缓存、重连、队列和 peer 身份。
2. 所有消费者经过同一数据选择结果；断开某来源仅使其候选失效，展示和告警不走两条不同数据链。
3. 输出按目标连接分区，指定双向复用连接；输入转发和系统观测编码分别声明来源与过滤。
4. 按用户答复接本机 NMEA App；明确服务端/客户端和实际汇总能力。

完成证据：两输入两输出真实并行，断开一个输入不干扰另一个；停止或堵塞一个输出时另一个继续；原样转发不回送；本机多消费者有真实状态和慢端隔离。重启恢复不能重新打开主动停止的连接/输出。

### 第四段：九 App 目录与内容收口

基础能力接通后同时切换目录与宿主，避免出现“标题已换，里面仍是旧工作区”的中间交付。

| 保留的稳定 ID | App | 旧入口兼容处理 |
| --- | --- | --- |
| chart | 海图 | sonar 到实测水深子功能 |
| chart_library | 海图库 | library / library:folderId |
| voyages | 航行日志 | trip 到当前航程；voyage/replay/report 到对应记录详情 |
| anchor | 锚警 | 直接新锚警宿主 |
| navigation | 我的航行 | places、place:、route:；anchorages 到锚地筛选 |
| instruments | 仪表 | data 的读数内容到仪表；sources 到系统来源选择 |
| nmea | NMEA 输入及输出 | 连接/指定连接输出；不含本机角色的模糊总 output |
| local_nmea | 本机 NMEA 客户端 | 新稳定 ID；明确本机职责后映射旧本机服务入口 |
| preferences | 设置 | 系统偏好与船舶资料；旧 marine-settings 逐项映射 |

磁贴保留用户 tileId、尺寸与位置；合并同目标时按明确迁移规则收敛，不强制九 App 全部铺 Start。默认仍沿原 Shell 的海图宽磁贴与设置小磁贴。

**必须先迁移再过滤目录：** 原 LauncherProductMigrationPlan 的早期步骤要求 data 已安装。删除 Data 后直接追加新计划会阻断 version 0 的升级。对 rebuild version 0 与旧版本 1/2 显式提供可完成的迁移路线，再统一到新版本。布局重置只重置 Start。

完成证据：旧安装升级后资料和布局保留；九 App 各自完成用户故事；没有旧全业务宿主在新标题下运行。

## 4. 手动验收场景

不先铺测试工程。以下是后续实现必须实际走通的短场景，不是声明已经通过。

1. **准备一次出航**：中英文各打开关键子页；选择手机位置并完成权限；选择命名海图；创建但不自动显示路线；手动选路线并从海图开始记录。
2. **航行途中下锚**：日志继续，锚警使用同一地图与新选点；切仪表、回 Start 再回锚警；结束记录不结束值守。
3. **多设备与断线**：两个 NMEA 输入分别提供船位与深度，同时向两个目标输出；一个输出堵塞时另一个继续；断开船位源，深度继续，船位明确失效；改用手机走同一系统流程。
4. **自己的海图**：一个文件夹建一层，两张重叠海图有优先级；切换三种来源无需退出；重扫、文件失效和权限修复不伪造成功。
5. **回顾与再利用**：结束航程、读事件并回放；收藏一次锚位，在我的航行补资料并用于新路线；原历史不被编辑收藏改写。
6. **全局一致性**：改船名、距离/速度/深度单位和磁贴显示，跨 App 即时一致；所有位置来源关闭时无隐藏手机位置请求。

涉及真实船网、传感器和用户海图的未验证项在交付说明中直接列明。不得把模拟回放、编译成功或旧 APK 的截图当作这些场景的通过证据。
