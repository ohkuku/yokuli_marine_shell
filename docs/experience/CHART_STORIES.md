# Chart 与我的航行：从计划到下一站

本轮围绕一个完整故事：**我选一条已经保存的航线，先弄清楚它怎么走，再明确开始导航；航行时始终知道下一个目标、距离和自己相对规划线的位置，最后由我确认到达或结束。**

Shell 仍使用原仓库的 WP8 磁贴、滑动、转场、应用会话和虚拟实体键。下面的变化只发生在 Chart / 我的航行应用内部。大标题、Pivot 和操作按钮沿用现有 WP8 视觉组件。

## 1. 我想从已有的计划中选下一段航程

入口是“我的航行”的“航线”Pivot。每条航线显示真实保存的名称、规划长度和航点数量。正在导航的路线单独显示当前目标，点一次就回到海图继续。

选择列表项只进入路线详情，不会启动导航，也不会把所有保存的路线画到海图上。没有航线时，页面解释如何在海图里用准星创建，并提供实际创建入口；导入 GPX 仍可带入原有路线。

## 2. 我想知道这条路线的形状、起点、终点和每一段

航线详情提供三个可滑动的 Pivot：

- **概览**：规划长度、航点数量、北向上的真实坐标草图、首点和终点。草图使用已保存的坐标，跨越 ±180° 的路线会展开经度以避免错误横跨整张图。
- **航点**：按顺序列出每个航点，显示上一点到这一点的距离、真方位和累计规划距离。点开后可以在海图定位，也可以将它作为第一导航目标。
- **整理**：编辑航点、重命名、创建反向返航副本、导出当前航线 GPX、删除。修改正在导航的路线前会明确结束该路线的导航；替换另一个未保存草稿前也会确认。

草图是路线形状预览，不伪装成海图。连接线和规划长度不表示水深、障碍或可航条件已被检查。

## 3. 我想先在海图看路线，再决定是否出发

“在海图上预览”只选中这一条路线，适配整条路线的地图范围，并出现一个简洁的“已选航线”卡片。卡片显示路线名称、长度、航点数以及“开始”操作。

如果另一条路线仍在导航，预览不会悄悄替换它；卡片提供“返回当前导航”。预览图上不会同时画出另一条路线的实时目标引导线。真正切换导航必须经过“开始沿线导航”的明确操作。

保存新路线仍然不会自动显示路线。路线预览可以隐藏，结束导航则会清除当前路线图形。

## 4. 我想明确选择先去哪里，然后开始

“开始沿线导航”先打开一个有内容的出发确认：

- 看到实际路线名称和候选航点。
- 默认从首点开始，也可以明确选择中途航点。
- 有新鲜船位时可以“选择最近的航点”；这是供用户确认的选择，不会自动开始或自动切换。
- 切换另一条正在导航的路线时，明确显示被替换的路线名称。
- 有定位时点“开始导航”；没有定位时可选择“开始并等待船位”，或直接去检查船位来源。

开始以后，当前目标和路线索引保存到已有会话存储中。定位可用时地图跟随船位；没有船位时先显示目标，距离、方位和偏离保持不可用状态。导航与航行轨迹记录是两件分别控制的操作，开始导航不会暗中启动或结束记录。

## 5. 航行中，我要一眼知道下一步

地图上的导航卡片优先显示：

- 路线名、当前目标序号 / 总航点数。
- 船位到目标的距离和真方位（°T）。
- 船位到当前目标、再经后续航点的剩余分段距离。
- 船位相对当前保存的规划航段的位置。

首个目标只有直接前往的距离与方位，因为没有一条已保存的“出发船位 → 首点”规划航段。后续目标使用球面几何计算相对上一航点到当前目标的横向偏离；在线段投影之外时显示“距规划航段”的最近端点距离，不把延长线上的零偏离误认为仍在航段内。文案是“规划线左侧 / 右侧”，没有“安全 / 不安全”判定。

地图同时突出当前目标，后续规划线保持强调色，较早的目标用灰色表示顺序位置。它们不冒充实际航迹；实际记录的航迹依然由记录系统提供。

导航卡片、准星读数和测距控件覆盖在地图上。出现或消失时不改变 native map 的视口尺寸，避免再次引入拖动时缩放和抖动。

## 6. 船位掉了，界面要讲清楚发生了什么

只使用已选择来源的真实 `Fix`，以既有单调时钟的 10 秒新鲜度判断是否可用于导航。失去来源或过期后：

- 路线和当前目标仍保留。
- 距离、总剩余距离、方位和横向偏离不继续冒充实时值。
- 卡片显示“等待船位 / 距离与偏离暂停更新”，可以直接打开来源页面。
- 当前有效定位精度可在导航详情中查看。

没有猜测位置、静默切换来源、虚构速度或填充假航行数字。

## 7. 我到了、想跳过一点，或者临时换目标

在新鲜船位距目标 50 m 内，且已知定位精度不差于 50 m 时，显示“目标附近（50 m 内）”。这是距离提示，不自动宣布到达，也不自动跳点。

用户可以：

- 明确确认到达，再前往下一点。
- 打开“切换目标航点”，查看完整目标列表并选择另一个点；之后继续按原顺序引导。
- 查看整条路线，或回到船位跟随。
- 在最后一个目标附近选择“确认到达终点”，再明确确认结束。

没有定位时仍可手动切换目标，路线计划照常保留，但实时指标继续保持空态。

## 8. 我结束了这段导航，要有明确收尾

“结束导航”会解释只结束当前引导，保存的路线仍在“我的航行”，航行记录由记录按钮单独控制。确认后清除活动目标、路线预览和跟随状态，保存会话，并给出明确的结束反馈。

如果用户确认到达终点，反馈为“已确认到达”。没有凭空生成已航行距离、用时或“成功安全抵达”的报告；实际航行报告属于真实记录会话。

## 9. 一个保存的地点，也能成为下一站

标记详情不再先呈现一整页编辑表单。“地点”页先展示坐标、已有备注，以及有新鲜船位时的真实距离和方位；“备注”页才提供名称和下次航行有用的信息编辑。

“前往这里”使用同一个明确的导航确认流程。确认开始后才保存单目标航线，同一标记使用稳定的路线标识，避免每点一次就生成重复路线。

## 实现范围

- `ui/PlacesScreen.kt`：我的航行列表、标记详情、航线概览 / 航点 / 整理。
- `ui/Navigation.kt`：导航测量、草图、开始确认、实时卡片、目标切换与结束流程。
- `ui/ChartScreen.kt`：在固定 native 视口之上显示选中预览或导航状态。
- `chart/ChartSurface.kt`：突出当前目标，区分规划顺序和实际记录，预览其他路线时不混画活动目标线。

不修改 Shell 模块，不添加自动避障、自动驾驶或假数据。
