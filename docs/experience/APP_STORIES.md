# Yokuli OS：应用的使用故事

> 历史方案，已被用户指出的领域混乱问题否定。当前整改以 [OS 领域模型](../product/OS_DOMAIN_MODEL.md) 与 [累积整改清单](../product/OS_REWORK_BACKLOG.md) 为准。下文保留作已有能力和演变记录，不再作为十二 App 目录或旧 UI 嵌入方式的实施依据。

基线：Shell 使用原 `codex/shell-map-contract` 的桌面、磁贴、滑动、转场和虚拟键。应用内容可以大胆发展。应用首页先呈现它所负责的事物，设置作为支持操作的入口。空态解释下一步；缺测、过期、演示和真实测量必须能分辨。

## 每个应用负责完成什么

| 应用 | 打开时应该看到什么 | 一段完整使用故事 | 结果留在哪里 |
| --- | --- | --- | --- |
| 海图 | 可直接拖动的海图、明确的船位、选中的航线与当前记录 | 查看船位 → 准星选点 → 标记/双图钉测距/规划 → 明确选择航线 → 沿线领航 → 确认到点、结束 | 标记、航线、航行记录 |
| 海图库 | 用户文件夹、命名图层、实际文件与覆盖范围 | 连接一个文件夹 → 扫描有效海图 → 创建命名图层 → 调整文件和图层优先级 → 查看覆盖、立即用于所有地图 | 用户原文件与本地来源索引 |
| 我的航行 | 自己的标记与航线，每条有可读的内容 | 打开路线草图 → 看每个航点和分段距离 → 选择起始目标 → 开始导航；也可修改、复制、GPX 导入导出 | 持久化的用户收藏 |
| 船舶数据 | 当前可信读数、变化曲线和来源 | 发现水深/风/速度变化 → 切换关注字段 → 触摸曲线读历史值 → 查看来源/年龄 → 需要长期保存时开始航行记录 | 最近15分钟进程内观察；完整航程另存 |
| NMEA | 船网输入、本机能力、船网输出和本机服务的实际流向 | 连接船网 → 看真实接收 → 冻结原始语句阅读与过滤 → 选择本机流向船网发布，或独立提供 TCP 服务 → 查看实际写出与客户端 | 连接配置、真实服务状态与有限诊断记录 |
| 航行记录 | 正在走过的航迹、距离、时长与沿途时刻 | 准备来源 → 出发 → 查看航迹形状和船况 → 给换帆/天气/注意点加命名备注 → 暂停/继续 → 结束保存 → 回放与导出 | 原有 Room 航程、样本、航点与事件 |
| 仪表 | 适合航行时阅读的读数、罗盘、运动和自定义页 | 选择航行/帆船/运动/天气 → 确认手机安装 → 查看真实船体空间姿态 → 切换空间/船尾/舷侧/俯视 → 点读数看质量和来源 | 原有仪表配置、安装状态和记录数据 |
| 航行日志 | 已完成的航程和可打开的记录 | 找到一次航程 → 阅读报告 → 跳到事件/航点回放 → 导出 CSV/GPX/KML/KMZ/图片或明确选择 AI 资料包 | 原有完整航程历史 |
| 锚警报 | 当前锚泊状态、船位轨迹、范围、警戒和可信度 | 选择或估算锚点 → 检查位置/半径/风水深条件 → 下锚值守 → 看轨迹和变化 → 告警处理/暂停/起锚 → 看历史 | 原有锚泊会话、轨迹与事件 |
| 锚地 | 自己的地点、照片、笔记、防护和到访记录 | 收藏一个地点 → 归入区域/集合 → 用距离方位接近 → 到访补笔记 → 分享或审阅导入 QR 卡 | 原有锚地数据库和用户媒体 |
| 个人水深图 | 自己实际测过的水深与调查 | 获取同服务器的位置和水深 → 选择潮汐改正 → 开始调查 → 在图上看样本/历史调查 → 管理调查与基准面 | 原有声呐样本、调查和潮汐数据 |
| 设置 | 外观与设备/船舶偏好 | 改语言、颜色、声音、船体参数或备份 → 返回当前应用继续使用 | Shell 偏好与原有业务配置 |

## 本轮新增的内容交互

- **路线使用**：[路线故事](CHART_STORIES.md)。保存、预览与导航分开；剩余距离、规划线偏离、目标选择和手动到达确认来自实际几何。没有自动声称路线可安全通航。
- **仪表空间表达**：[仪表故事](INSTRUMENT_STORIES.md)。用船体网格投影表达横倾和纵倾，四种视角回答不同读数问题。未安装、缺失和过期只显示明确的示意轮廓，不把水平模型当成实测零度。
- **NMEA 实况**：[NMEA 故事](NMEA_STORIES.md)。原连接/输出功能完整保留，首页变为实际流向与可操作的语句阅读。冻结查看不停止服务。
- **数据变化**：不同字段的真实观察进入最多15分钟的内存曲线；可触摸读取某一时刻，断线、来源变化和角度跨零点断开绘制。数值过期后当前大字显示缺测，历史仍明确是过去。
- **航行过程**：当前航迹的北向上草图可打开真实海图；航况页关注航速、水深、风和气压；命名的沿途时刻带备注和分类，保存时由原记录引擎采集实际船位与船况；完成航程可回放或导出 GPX。

## 交互约束

1. 原 Shell 管应用生命周期和返回。应用内部滑动切换内容；子页左上返回和虚拟返回都先退一级。
2. 丰富内容通过可操作的地图、轨迹、曲线、空间姿态、记录和用户作品呈现；缺少数据时说明如何获取，不填演示数字。
3. 连接、数据采集、记录和显示各有真实状态。启用配置不是已连接，已连接不是有新数据，发送请求不是实际写出。
4. 图形帮助理解事实。船体图不是稳性模型；航迹草图不是航海底图；路线偏离不是障碍判断；实测水深不是测绘认证。
5. 中英文同步，方角按钮、大字标题和横滑内容遵从 WP8。后续功能继续从具体故事扩展，不把每个新能力都做成一级页面。

这一轮保留手动体验优先：编译和少量针对实际问题的操作检查，之后由真实海图、真实船网、手机传感器和航行场景检验内容与操作是否成立。
